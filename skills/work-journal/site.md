# ChatGPT Site journal

## Agent boundary and handoff

Codex/ChatGPT, with the current Sites plugin and its `sites` skill, does all Site inspection, source changes, preview, deployment, and sharing. A non-OpenAI agent prepares the reviewed content and hands this stage off; it never recreates the Site elsewhere or reaches it through a browser workaround. Set up the handoff in preflight so the dependency is known before research runs.

The handoff carries:

- The reporting week, exact bounds and timezone, the approved full draft, the selected Slack highlights, and open uncertainties.
- Review decisions, intentional exclusions, and any authorization already given for deployment, sending, or sharing changes.
- The project ID and URL, the intended archive route, a source checkout location if one exists, and this reference.
- Next actions and source access gaps. Transfer file contents, not local paths the receiving environment cannot read, and never credentials.

Codex/ChatGPT verifies Sites access and the project before continuing, then returns the deployed week link and verification result. Slack highlights stay draft-only until that link works and sending is authorized.

Read the live deployment and audience state rather than trusting a saved version ID. The Site is public with coworker invitations deferred until Winnie is ready; keep that unless she asks otherwise, and never deactivate weekly history.

## Weekly update

Follow the installed Sites skill's workflow for opening the source, credentials, packaging, and deployment. The helper owns source commits and pushes; credentials stay in memory and hidden stdin, never in notes, arguments, or archives. Save and deploy with the exact source SHA or archive that workflow returns.

The source is buildless HTML, CSS, and JS generated by Python's standard library:

| File | Responsibility |
| --- | --- |
| `weeks.json` | Manifest: week IDs, Monday and Friday dates, ISO week and year, quarter, source Markdown filename |
| `build.py` | Parses sources, embeds journal data, generates static week routes, copies assets |
| `template.html`, `app.js` | Layout, rendering, categories, filters, history, source links |
| `navigation.mjs` | Calendar and week and keyboard navigation |
| `navigation.test.mjs`, `app.test.mjs` | Node behavior checks |

Every week has its own Markdown snapshot, so a published week is never edited through a shared file. Before touching a source file, check which manifest records reference it and freeze any published week into its own file. The reporting week gets a new source and manifest record with a unique ID and consistent dates; edit an existing record only to revise that same week. Retain every week; the builder removes generated routes the manifest no longer lists.

From the checkout:

```sh
python3 build.py
node --test navigation.test.mjs app.test.mjs
```

Check the generated content against the approved draft: item count, groups, statuses, citations, period, and no review notes or private research. Confirm `/` selects the latest week, archive links open their week, and retained weeks keep their content. Preview visually when browser tools exist; otherwise report the gap rather than claiming visual verification.

Deploy through the Sites workflow with the audience preserved, confirm the week link opens, and record the returned source SHA, version and deployment IDs, route, and URL in the publication receipt.

## Preserve the shared design

A weekly update changes content, not design; the source is the authority on layout, typography, navigation, and keyboard behavior, and the tests guard the navigation contract. Brand constants to keep: warm white `#f8f7f2`, purples `#5E4CFF`, `#9D8DFF`, `#EFECFF`, Windash branding with the supplied Espeon logo in `assets/windash.png`, and platform icons with their license and provenance in `assets/icons/`. Brand reference is https://lightdash-asset-lab.vercel.app/#style. Status, category, and link conventions are in [presentation](presentation.md).

The date is the main header: purple uppercase sans-serif text with arrows at opposite ends; mobile shows only the month/day range. Omit introductory copy, journal subtitles, identity footers, and section numbers. Customer names use the same heading style as Scoped and Shipped. Status buttons toggle independently, all enabled initially, with raised, hover, and depressed states; there is no All button.
